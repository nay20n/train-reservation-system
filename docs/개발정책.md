## 회원

| 항목 | 정책 |
| --- | --- |
| 비밀번호 저장 | BCrypt로 암호화해서 저장 (`spring-security-crypto`만 사용, Spring Security 전체는 쓰지 않음) |
| 로그인 실패 | 아이디가 없든 비밀번호가 틀리든 `401 LOGIN_FAILED` 하나로 응답 (가입 여부를 알 수 없게) |
| 로그인 상태 | 서버는 기억하지 않음. 로그인 응답의 `memberId`를 프론트가 저장해서 보냄 |
| 로그아웃 | 서버 API 없음. 프론트가 저장한 `memberId`를 지우면 끝 |
| 회원상태 (`member_status`) | `ACTIVE`(정상) / `WITHDRAWN`(탈퇴). 가입 시 `ACTIVE` |
| 아이디 중복 | 가입 전에 확인 + DB 유니크 제약으로 한 번 더 막음. 둘 다 `409 DUPLICATE_LOGIN_ID` |

> 참고: 지금 방식은 `memberId`만 바꿔 보내면 다른 회원 정보에 접근할 수 있어요.
> 보안을 강화하려면 나중에 세션이나 토큰 방식으로 바꾸는 걸 검토해요. (명세 변경 필요)

## DB / SQL

- SQL 파일은 모두 `src/main/resources/db/`에 둬요.
  - `schema.sql`: 테이블 생성. 서버 시작 시 자동 실행 (`CREATE TABLE IF NOT EXISTS`)
  - `data.sql`: 기준 데이터. 서버를 켤 때마다 실행되므로 `INSERT IGNORE` + ID 직접 지정
- 테이블 구조를 바꾸면 `schema.sql`만 고쳐서는 반영 안 돼요. 해당 테이블을 DROP하고 서버를 다시 켜야 해요.
- 회원상태처럼 명세에 없는 내부 값은 영어, 명세에 있는 상태값(`예약대기`, `결제완료` 등)은 명세의 한글 그대로 저장해요.

## 패키지 구조

기능(도메인)별로 나누고, 각 패키지 안에 Entity / Repository / Service / Controller / dto를 둬요.

| 패키지 | 테이블 |
| --- | --- |
| `member` | member |
| `station` | station |
| `train` | train, seat, train_run, train_stop, fare |
| `reservation` | reservation, reservation_detail, passenger, ticket |
| `payment` | payment, refund |
| `global` | 공통 (예외 처리 등) |
